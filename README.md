# pgp_sequential

Sequential experimental design for projection-based reduced-order models (ROMs)
using a **projected Gaussian process (pGP)** on the Grassmann manifold.

At each step the method fits a pGP to the parameter → POD-subspace map, estimates the
posterior **manifold variance (MMV)** via Monte-Carlo sampling and geodesic distances,
and selects the next full-order simulation where the MMV is largest. This concentrates
expensive high-fidelity runs where the reduced subspace changes most rapidly.

Reference: *Projected Gaussian Process for the Design of Experiments in High-Dimensional Models.*

## Layout

```
pgp/                     Core algorithm (single package; all kernels + CGP)
├── projectGP.py         pGP model on the Grassmannian (fit / predict / MMV sampling)
├── estimation.py        kernel library (rbf, matern52, poly_rbf, gibbs, cgp) + MAP fit
├── cgp_optim.py         CGP composite-kernel optimizer (LHD screening + IRLS + L-BFGS)
├── manifold.py          Grassmann geometry: log/exp maps, geodesic distances, Karcher mean
├── data.py              input normalizers (z-score, log-space)
└── kl_expansion.py      Karhunen–Loève expansion (Darcy log-permeability field)

experiments/
├── run_comparison.py    sequential-design driver (the 4 methods below)
└── acquisition.py       acquisition-function components (variance / diversity / interior)

simulators/              full-order PDE solvers that generate snapshot data
├── simulate_advecdiff.R     2D advection-diffusion (needs R)
├── simulate_darcy.py        5D Darcy flow (pure Python)
├── fom_rom_adjoint.R
└── simulate_precompute.R
```

## Methods

| key                       | description                                        |
|---------------------------|----------------------------------------------------|
| `proposed_matern52`       | pGP-MMV with a stationary Matérn-5/2 kernel        |
| `proposed_cgp_ktheta_r`   | pGP-MMV with the nonstationary CGP kernel (Ba & Joseph, 2012) |
| `maxpro`                  | space-filling MaxPro design (baseline)             |
| `greedy_replay`           | model-constrained greedy / MC Greedy (baseline)*   |

\* `greedy_replay` replays a precomputed greedy trajectory; pass its log via
`--greedy-log-path`. The core comparison is Matérn vs CGP vs MaxPro.

## Install

```bash
pip install -r requirements.txt
```

## Run

```bash
python experiments/run_comparison.py \
    --config config.yaml \
    --methods proposed_matern52 proposed_cgp_ktheta_r maxpro \
    --seed 42 --steps 30 \
    --results-dir results/demo
```

The driver calls `simulators/` to generate the full-order snapshots on demand, fits the
pGP, and writes per-method `*_log.json` (per-step MMV / projection RMSE / geodesic error /
POD-angle metrics) plus `train_meta.csv` under `--results-dir`.

## Minimal config (`config.yaml`)

2D advection-diffusion example (five KL/diffusion settings, 30 sequential steps):

```yaml
problem: advecdiff
domain:
  dx_bounds: [1.0e-4, 1.0e-2]
  dy_bounds: [1.0e-4, 1.0e-2]
normalizer: log
design:
  n_init: 5          # initial space-filling design size
  n_steps: 30        # sequential points to add
  batch_size: 1
  n_cand: 512        # Sobol candidate pool per step
  seed: <your_seed>  # any integer; controls initial design / candidates / MC
gp:
  kernel: matern52   # overridden per-method (cgp for proposed_cgp_ktheta_r)
  pod_modes: 5       # POD truncation rank r
  mc_samples: 100    # MC samples for the manifold-variance estimate
  reference: karcher # Grassmann reference point (fixed across steps)
  restart_interval: 0
test_grid:
  n_grid: 6          # held-out test grid for evaluation
  n_rand: 14
acquisition:
  preset: pure_mmv
methods:
  - proposed_matern52
  - proposed_cgp_ktheta_r
  - maxpro
execution:
  workers: 1
```

For the 5D Darcy flow example set `problem: darcy`, `pod_modes: 3`, `mc_samples: 500`,
`n_init: 100`, and a 5D KL parameter domain (see `simulators/simulate_darcy.py`).

## Data

Full-order snapshots (large `snapshots/` CSVs) are **not** version-controlled — they are
regenerated by `simulators/` from the config. Only the small per-step `*_log.json`
metric files are meant to be kept.
